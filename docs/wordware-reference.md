# Wordware 风格来源与改写

核对日期：2026-09-24。公开来源为 [Wordware 官方仓库中的 `roastPrompt`](https://github.com/wordware-ai/twitter/blob/main/src/lib/prompts.ts)。该文件的注释把 roast/full 描述为原发布应用的提示词；我们只据公开文件确认来源，没有独立核实所有历史版本。

原文短摘：“The roast should be clever, edgy, provocative and focus solely on twitter data. Aim for roasts that are brutal.”

本项目只借鉴“围绕具体输入写得尖锐”的方向。实际运行的 [现场 Prompt](../src/lib/prompt.ts) 是针对照片、现场背景与粗粒度地点重新编写的中文版本，加入事实约束、隐私边界和结构化输出。没有复制 Twitter 抓取、星座口吻、个人画像或上游完整代码。公开仓库不等于其全部材料可无条件复制商用。

## v0.2 风格调整与实测

用户反馈 v0.1 的真实生成结果偏抒情、不够锋利。v0.2 将目标改为短促的现场热评，要求直接开损、结尾补刀，并移除原有的具体示例，避免模型把示例事实搬到用户场景。它仍然只使用照片和用户提供的现场信息，不等同于 Wordware 针对推特账号本人的 roast。

用一条虚构的无图堵车场景做单次人工抽查：`qwen3-vl-flash`、`qwen3-vl-plus`、`qwen3.8-flash`、`qwen3.7-plus`、`qwen-flash-character` 均曾输出未给出的现场细节或时间推断，`qwen3.8-max` 的一次结果不符合三条结构。仅更换模型没有证明文案质量达标；需要在更多真实且获授权的场景上继续人工评审。`tests/roast-cases.json` 中的 `traffic-text-only` 记录这次发现的事实边界。

## v0.3 风格调整与同输入对照

用户给出的“完整的风格升级补丁”位置仍是占位文字，未包含补丁正文。v0.3 依据已明确的目标，替换了角色、毒舌风格、三条写法和再损一点规则；保留事实、隐私和安全边界。完整提示词继续只在服务端生成路径使用。

2026-09-24 用同一条虚构的无图文字输入“下雨天等公交二十分钟，车到站时刚好开走。”做单次模型对照，均走相同 JSON 协议。结果是模型原样输出，不是手写示例：

| 配置 | 单次耗时 | 观察 |
| --- | ---: | --- |
| `qwen3-vl-flash` + v0.2 | 1.8 秒 | 三条齐全，但编出手机电量变化。 |
| `qwen3-vl-flash` + v0.3 最终提示词 | 1.9 秒 | 三条齐全，仍编出“末班车”“系统安排”，毒舌与事实准确度仍不达标。 |
| `deepseek-v4.1-flash` + v0.3 早期提示词，默认思考 | 21.5 秒 | 三条更贴近已知情境、讽刺更明确；仍有“淋雨”等未确认细节。 |
| `deepseek-v4.1-flash` + v0.3 最终提示词，低强度思考 | 26.5 秒 | 三条基本贴题；速度没有改善，仍把下雨推成“淋雨”。 |
| `deepseek-v4.1-flash` + v0.3 最终提示词，关闭思考 | 2.9 秒 | 三条齐全但语气又变浅，还补出车门动作。 |

这是一条输入、每种设置一次的探索性结果，没有视觉输入；不能据此证明某模型整体质量更好，也不能宣称 v0.3 已达到“越毒越好”。随后按用户要求将本地运行配置改为 `deepseek-v4.1-flash` 试用，并在页面提示等待时间；仍需更多文字与照片场景评审。

同输入的原始三条输出，便于直接比较：

**Qwen + v0.2（修改前）**

1. 雨天等公交二十分钟，车到站时刚好开走——这哪是等车，这是给公交车送行的VIP席位。
2. 二十分钟没动，手机电量从87%掉到79%，连被淋湿的焦虑都比电量跑得快。
3. 车一到站就开走，仿佛它不是来接人的，是来提醒你：今天运气值已清零，明天请重装系统。

**Qwen + v0.3 最终提示词（修改后，当时配置）**

1. 雨天等公交二十分钟，车到站时刚好开走——这哪是末班车，这是‘误点特快’，专治各种不服。
2. 二十分钟的等待，换来了一个精准的‘错过’：你不是没赶上车，你是被系统安排好了‘恰巧错过’。
3. 下雨天等公交，结果车一到就走——这叫‘时间管理大师’，连迟到都提前替你算准了。

**DeepSeek + v0.3 最终提示词（低强度思考，模型比较用）**

1. 下雨天等二十分钟，公交到站和开走无缝衔接，唯独没给你留上车的缝。这到站是给站牌看的。
2. 等二十分钟换来一个刚好开走，下雨天公交的准点，准在让你赶不上。
3. 二十分钟等来它到站，也等来它开走；你唯一的参与感是淋雨。

## DeepSeek 接入验收

在本地服务使用百炼 `deepseek-v4.1-flash`、默认思考模式与 v0.3 提示词，通过真实 `/api/roast` 接口验证：

- 虚构的纯文字公交场景：HTTP 200、`mode=live`、`status=ok`、三条结果，约 21.1 秒。
- 一张程序绘制的公交图和虚构文字背景：HTTP 200、`mode=live`、`status=ok`、三条结果，约 16.6 秒。该图仅验证图片上传与视觉模型接入，不算真实照片质量验收。
- 当时的浏览器页面在提交前显示“当前使用深度思考模式，生成可能需要约 20～35 秒”，生成时另显示“正在深度思考这次的槽点，请稍等”。随后已改为快速优先、深度可选。

这两次接口测试都没有使用真实用户照片或位置。生成时长是单次观测，不保证每次都落在该区间；当时服务端设 35 秒超时。

## 快速优先与等候小游戏

2026-09-24 使用同一条虚构、无图的公交文字输入再次调用真实 `/api/roast`：`generationMode=fast` 为 HTTP 200、三条结果，约 6.4 秒；`generationMode=deep` 为 HTTP 200、三条不同结果，约 18.0 秒。无效模式返回 HTTP 400。浏览器里首次快速请求显示三条结果和“深度开喷”入口；点击后可在等待期间切换“真心话 / 嘴上大冒险”并换题。该次浏览器深度请求超过原来的 35 秒超时，出现了明确错误。由此将深度请求上限调到 60 秒，快速请求保留 35 秒上限。随后用同一页面重试深度生成，成功显示三条新结果和“AI 生成 · 深度版”，小游戏保留在页面上。以上仍是少量样例，不能保证文案质量或时长。
